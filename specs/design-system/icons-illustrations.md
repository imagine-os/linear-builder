# PAP-68: Choose the icon set (Lucide or Phosphor) and illustration style; build a tree-shaken Icon component

**Goal**

Pick one icon set and one illustration style for all PaperOS surfaces and ship a tree-shaken `Icon` component plus an `Illustration` component so agents never paste ad-hoc SVGs or mix icon families.

**Scope**

In:
- Decision between Lucide (`lucide-react` 0.5xx) and Phosphor (`@phosphor-icons/react` 2.x) scored on coverage for our domains (finance, tables, collaboration), weight variants, licence, bundle behaviour, agent familiarity. Default recommendation: Lucide.
- `packages/ui/src/components/icon/` with `Icon` wrapper (`size` token, `tone`, `label` for accessible name, `decorative` default), re-exporting icons by name.
- Custom icon pipeline: `packages/ui/icons/custom/*.svg` optimised by SVGO and converted to React components with `@svgr/cli`, matching stroke width 1.5 and 24px grid.
- Illustration style guide (two-tone line illustrations using `color.accent` and `color.fg.muted` tokens), six starter illustrations: empty, error, offline, no-permission, success, onboarding, as `Illustration name="empty"`.
- Icon catalogue story with search.

Out: brand logo work, animated icons, emoji policy (docs guidelines).

**Spec**

- `Icon` props: `{ name: IconName; size?: 'xs'|'sm'|'md'|'lg'|'xl' (12/16/20/24/32); label?: string; className? }`. Renders `aria-hidden` unless `label` provided, then `role="img" aria-label`.
- `IconName` is a string union generated by `pnpm --filter ui icons:gen` from the chosen library's export list plus custom icons; a build fails if a spec references a missing name (consumed by `design-system/component-spec-mapping`).
- Tree-shaking: import per icon (`import { Plus } from 'lucide-react'`) inside a generated map with lazy `React.lazy` for the dynamic-by-name path used by specs; static usage stays direct.
- Illustrations use `currentColor` and CSS variables only; no embedded fills; `Illustration` sizes `sm|md|lg` (120/200/320px), always `aria-hidden` with adjacent text required.
- Stroke width follows `--pos-icon-stroke` (1.5 default, 2 in high-contrast theme).
- ADR `docs/adr/0004-iconography.md` records scores and the decision.

**Definition of done**

- ADR merged; `Icon` and `Illustration` components with stories and Vitest tests.
- Dynamic icon by name works from a spec fixture; unknown name renders a dev placeholder and logs.
- `size-limit`: app importing five icons adds under 3 KB gzipped.
- Six illustrations render correctly in light, dark and high-contrast; screenshots at 375 and 1280.
- Catalogue story searchable; `docs/design/icons.md` written.
- CHANGELOG entry; Linear comment with Storybook link.

**Edge cases**

- Icon-only buttons must receive `label` or the a11y test fails (`IconButton` enforces at type level).
- RTL: directional icons (`arrow-left`, `chevron-right`) flip via `rtl:-scale-x-100` when `flipInRtl` is true.
- High-DPI blurriness at odd sizes: sizes locked to the token set; fractional sizes rejected.
- Icon library major-version rename of icons: the generated union pins names and CI fails on removal.
- Print styles: illustrations hidden, icons keep `currentColor`.
- Windows high-contrast mode (`forced-colors: active`): strokes use `CanvasText`.

**Dependencies**

`design-system/tokens` (sizes, colours). Soft: `libraries/eval-rubric` for scoring format. Consumed by `design-system/primitives` (Button icons), `design-system/data-display` (EmptyState), `design-system/component-spec-mapping`.

**Agent**

Built by Iris (Component Crafter) with Scout (Library Evaluator) supplying the comparison. Reviewed by Sentinel (Code Reviewer) and Quill for the ADR.

**Size**

S: one decision and two thin components; the generated name union is the only moving part.
