# PAP-685: Quality handbook: one page that explains the four gates, how to read a PR's evidence, how to update baselines, waive a finding, quarantine a flake and rehearse a release

**Model / Effort:** Haiku 4.5 (`claude-haiku-4-5-20251001`) / low — Docs S

**Goal**

Each gate issue writes its own section of `docs/quality/*.md`, so by the release week there are fourteen documents and no front door. The handbook is the single page Justin or a new character opens to understand what a green PR means, what every status badge is, where the evidence lives and which one-line action fixes the common red states.

**Scope**

* In: `docs/quality/README.md` (handbook index) and `docs/quality/how-to/{read-a-pr,update-baselines,waive-a-finding,quarantine-a-flake,rehearse-a-release,run-gates-locally}.md`, a generated status table from `GATE_STATUSES` (PAP-239) with owner issue and artefact per status, a glossary, links from `CLAUDE.md`, the PR template (PAP-49) and the session playbook (PAP-92).
* Out: per-gate reference docs (each gate issue), the rubrics (PAP-79), the character handbook (PAP-112).

**Spec**

* Index under 900 words: the four gates in one diagram (Mermaid), the status table generated by `pnpm docs:gates-table` from `GATE_STATUSES` and the docs frontmatter of each gate page (`status`, `artifact`, `owner`), the evidence map (sticky comment sections, Pages URLs, Linear status comment), the three rules Justin cares about (any S0 blocks, more than 3 S1 blocks, baselines change only through the label).
* How-to pages each under 400 words with the exact command or label: `update-baselines` label (PAP-247), waiver file and who may approve (PAP-80), `Flaky:` issue flow (PAP-90), `rehearsal` label and `/approve` (PAP-254), `pnpm check`, `pnpm shots`, `pnpm e2e --grep @smoke` locally (PAP-78, PAP-82, PAP-86).
* Glossary: gate, finding, severity, rubric id, baseline, contact sheet, quarantine, release candidate, certification, digest, waiver.
* Lint: `pnpm docs:lint` (PAP-128) link check plus a test that every status in `GATE_STATUSES` appears in the table.

**Interface contract**

* Provides: `docs/quality/README.md`, how-to pages, `pnpm docs:gates-table`, the frontmatter convention `status`, `artifact`, `owner` for gate docs.
* Consumes: PAP-239 `GATE_STATUSES`, the gate docs written by PAP-78 to PAP-90, PAP-128 docs lint, PAP-49 and PAP-92 for links.

**Definition of done**

* Index and six how-to pages merged; status table lists every registered status with owner and artefact (test).
* Read-through by Justin in a comment: he can name the three blocking rules and find a PR's screenshots from the page alone.
* Links from `CLAUDE.md`, PR template and playbook merged; changelog under "Docs".

**Test plan**

* Unit: status table generator against a fixture registry; link lint.
* E2E: none beyond docs lint; screenshot of the rendered index at 375 and 1280 px through the docs engine when PAP-128 lands.

**Demo**

Open `docs/quality/README.md`, follow "read a PR" to a real PR's sticky comment, then "update baselines" to the label workflow. Under one minute.

**Edge cases**

* A gate lands after the handbook: its doc frontmatter adds it to the table; the lint fails until it does.
* Status renamed in PAP-239: table regenerates; prose references are caught by the link check.
* Docs engine not yet live: pages readable on the forge with relative links.

**Dependencies**

Hard: PAP-78, PAP-243, PAP-246. Soft: PAP-239, PAP-128, PAP-49, PAP-92.

**Agent**

Builder: Quill (Changelog Scribe). Reviewer: Sentinel (Code Reviewer).

**Size**

S: half a session.
