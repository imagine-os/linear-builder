# PAP-445: Build the module docs generator: one page per module from manifest, contract exports, conformance case ids, bindings, slots, events and dependency edges into the docs engine

**Model / Effort:** Sonnet 5 / medium

**Goal**

Generate the documentation the Module System promises instead of writing it by hand: `docs/platform/modules/<id>.md` and `docs/platform/contracts/<id>.md` produced from the manifest, the contract package's exports and schemas, the conformance suite's case ids, the kernel's bindings, the slot and topic registries and the dependency map, rendered in the docs engine (PAP-128) and kept fresh by a Gate 1 drift check.

**Scope**

In:

* `pnpm gen:module-docs`: per module a page with identity and owner, swap risk and kind, provides (ports with signatures from TypeScript, schemas rendered from JSON Schema), requires (with matrix cells), slots exposed and filled, topics published and subscribed (from `topics.json`), routes (from `routes.json`), conformance cases and last artefact link, bindings and flags (from `kernel.describe()`), Linear issues (from manifests and the map).
* Index page with the module table (mirrors `docs/module-system.md` table 1.1, generated so it cannot drift) and the Mermaid dependency map.
* Templates in `tools/module-docs/templates/*.mdx`; output committed; drift check in Gate 1.
* Docs engine registration (PAP-128 `DocsPort.publish`) and search indexing (PAP-39).

Out: prose (Goal and rationale stay in the hand-written `docs/module-system.md` and ADRs), diagrams beyond Mermaid (Blueprint views).

**Spec**

* Generated pages carry a header `generated by pnpm gen:module-docs; edit templates, not this file`.
* TypeScript signatures come from the contract package's `.d.ts` via `ts-morph`; JSON Schema rendering uses one shared component.
* Missing inputs (no conformance yet, no bindings) render as `pending` sections, never as errors, so pages exist from the first contract issue onward.
* Runtime under 30 s for eighteen modules.

**Interface contract**

Provides: `pnpm gen:module-docs`, templates, the generated pages and index, Gate 1 step `module-docs`. Consumes: manifests, contract packages, `topics.json`, `routes.json`, `dependency-map.json`, `compat-matrix.json`, `conformance.json` artefacts, `kernel.describe()`, PAP-128 docs engine, PAP-39 search. Consumed by: every contract and wire issue (their Definition of done cites the generated page), PAP-24 template guide, PAP-112 character handbook (owner links), the Blueprint.

**Test plan**

* Golden: generated pages for the fixture workspace match committed snapshots; drift check fails on a hand edit.
* Unit: `pending` rendering for each missing input; signature extraction on a sample contract.
* Integration: pages render in the docs engine with working anchors and search hits for a port name.

**Definition of done**

* Generator merged; pages committed for every module with at least a manifest; docs engine renders them; drift step in Gate 1.
* Linear comment with the index link.

**Edge cases**

* A contract with hundreds of exports (tables): sections collapse by port; the page stays under 200 KB.
* Generated page referenced by a Linear issue before regeneration: anchors are stable (port names), not positional.
* Docs engine not yet merged: pages are still generated and committed; publishing is skipped with a note.

**Dependencies**

Blocked by module-system/manifest-schema, module-system/dependency-lint-and-map, PAP-128.

**Agent**

Built by Quill. Reviewed by Forge.

**Size**

S

**Demo**

Reviewer opens `/docs/platform/modules/tables` in the app and sees ports, slots, topics, routes, conformance cases and the four consumers; edits the page by hand and Gate 1 fails with `module-docs` drift. Under a minute.
