# PAP-727: Agent-readable docs: `llms.txt`, raw Markdown endpoint per page, `pnpm docs search|get` CLI and a docs MCP tool

**Model / Effort:** Sonnet 5 (`claude-sonnet-5`) / medium — Build S

**Goal**

The docs engine renders MDX for humans; a cold Claude session needs the same knowledge as plain text without booting a browser. Mintlify and Docusaurus ship `llms.txt` and `.md` mirrors for exactly this reason. Emit them at build, add a CLI and an MCP tool so sessions and reviewers read docs the same way the UI does.

**Scope**

In: `pnpm docs:llms` in `packages/collab/docs/` writing `docs/.generated/llms.txt` (index with one line per published doc) and `llms-full.txt` (concatenated, audience `developer|agent` only); route `/_public/docs/$.md` and `/_app/docs/$.md` returning the compiled Markdown (MDX components rendered to text by `renderMdx` text mode); CLI `pnpm docs search <q> [--kind doc|adr|rule]` and `pnpm docs get <slug>`; MCP server `packages/agents/mcp/docs/` (stdio, `@modelcontextprotocol/sdk` 1.x) exposing `search`, `get`, `list` with `scope: read`, catalogued in PAP-210 `mcp-catalog.yaml`. Out: Q&A answers (PAP-735), external docs.

**Spec**

* `llms.txt` follows the [llmstxt.org](<http://llmstxt.org>) shape: H1 title, blockquote summary, sections per docs folder with `[title](url): description`; regenerated by `pnpm docs:index`; under 200 KB or split by folder.
* `.md` route strips `Callout`, `Steps`, `Tabs`, `FileRef` (inlined), `Mermaid` (fenced \`\`\`mermaid) to plain Markdown; audience rules identical to the HTML routes; `Cache-Control: max-age=300`.
* CLI reads `docs/.generated/sidebar.json` and, when a database is configured, `search.query` from PAP-39 with `kinds: ['doc','adr','rule_skill']`; offline fallback greps the generated index.
* MCP tool descriptions are one sentence each; tool output capped at 20 KB per call with a `truncated` flag and a `next` cursor.
* The session playbook (PAP-92) and CLAUDE.md gain one line: `pnpm docs search` before asking a human.

**Interface contract**

Provides: `llms.txt`, `llms-full.txt`, `.md` routes, `pnpm docs search|get`, MCP server `@paperos/mcp-docs` with tools `mcp__paperos-docs__search|get|list`, catalog entry. Consumes: `DocEntry`, `renderMdx` text mode and `sidebar.json` (PAP-128), `search.query` (PAP-39, PAP-138 soft), MCP catalog schema (PAP-210), agent skill lint (PAP-105 soft). Consumed by: PAP-109 memory loader, PAP-92 playbook, review harness PAP-243 (context assembly), Scout scans (PAP-218).

**Definition of done**

* `llms.txt` and `.md` mirrors generated in CI for the template docs; a staff-only doc is absent from the public `llms.txt`.
* `pnpm docs search 'quality gates'` returns the gate doc first; MCP server lists three tools in a fresh Claude Code session (`/mcp` screenshot).
* `docs/collab/agent-docs.md`; CHANGELOG entry; comment on PAP-210 with the catalog entry.

**Test plan**

* Unit: MDX to Markdown conversion fixtures for every component, audience filtering of `llms.txt`, output cap and cursor.
* Integration: `.md` route via `callAs(customer)` for a staff doc returns 404; MCP server tools tested with the SDK in-memory transport.
* E2E: none (no UI); CLI smoke in Gate 1.

**Demo**

Run `pnpm docs search hocuspocus`, open the hit with `pnpm docs get`, then curl `/_public/docs/getting-started.md` and diff it against the HTML page's text. Under one minute.

**Edge cases**

* Doc with only Mermaid content: fenced block kept, summary generated from the title.
* 10k-word doc: `.md` served whole; `llms-full.txt` includes the first 2k words plus a link.
* Search backend down: CLI falls back to the static index with a notice.
