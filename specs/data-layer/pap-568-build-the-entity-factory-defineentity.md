# PAP-568: Build the entity factory: `defineEntity()` yields the Drizzle repository, CRUD oRPC router, Zod DTOs, shape registration, audit reason handling and `record.*` events from one declaration

**Model / Effort:** Opus 5 (`claude-opus-5`) / high — Build L

**Goal**

What a cold Claude session needs most and nothing owns: one call that turns a Drizzle table into a conformant module entity. PAP-268 hand-writes core routers, PAP-448 only declares `RepositoryPort<T>`, and every module (PM, CRM, finance, import) would re-implement CRUD with cursors, filters, audit and events. `defineEntity()` generates it once, the way Supabase and Hasura auto-CRUD do, and keeps twenty parallel sessions from drifting.

**Scope**

In: `packages/db/src/entity/{define,repository}.ts` (Drizzle implementation of `RepositoryPort<T>` and `UnitOfWork`), `packages/api-contract/src/entity/router.ts` (router generator), `packages/sync` shape registration hook, `packages/db/src/entity/testing.ts` (contract test any entity passes), `docs/data/entities.md` cookbook 'Add an entity in ten minutes', conversion of `workspaces`, `memberships` and `files` routers to the factory.

Out: Custom datasets (PAP-161, PAP-164), view compilation (PAP-163), record detail UI (PAP-333), policies (PAP-227).

**Spec**

* `defineEntity({ table, key: 'invoice', dto, filterFields: FieldSchema, sortable, shape?, audit: { reason: 'agents'|'always'|'never' }, events: true, hooks })` returns `{ repo, router, shape, schemas, key }`.
* Repository `get`, `list({ cursor, limit<=100, filter?: FilterTree, sort? })`, `create`, `update`, `archive`, `restore`, `bulk({ ids, patch })` (cap 500) through `withTenant`; list uses `toSql` (PAP-279) and `signCursor` (PAP-302); errors map per Contracts §4.
* Router `router.<key>.<verb>` via `defineRouter` (PAP-268) with `authorize('<key>.<verb>')` (PAP-229), `idempotent()` on create and archive, `X-PaperOS-Reason` mapped to `app.reason` (PAP-38).
* Events: `record.created|updated|deleted` published in the same transaction with `subject = { type: key, id }` and changed field names only (PAP-555); hooks may publish domain topics.
* `sync: true` registers a shape with tenant and PAP-228 permission predicates; encrypted columns (PAP-353) excluded automatically.
* Optimistic concurrency: `update` accepts `ifUpdatedAt` and returns 409 with `{ server: row }` (the shape PAP-148 expects).
* `entityConformance(definition)` runs the PAP-451 repository cases against any entity in CI.

**Interface contract**

Provides: `defineEntity`, `DrizzleRepository<T>` implementing `RepositoryPort<T>`, `UnitOfWork` via `withTenant`, generated `router.<key>.*`, `entityConformance`, cookbook doc.

Consumes: Routers and `callAs` (PAP-268), `toSql` (PAP-279), cursors and error body (PAP-302), `publish` (PAP-555), audit vars (PAP-38), `authorize` (PAP-229, soft), idempotency (PAP-557, soft), shapes (PAP-270/271, soft), predicates (PAP-228, soft). Consumed by PAP-100, PAP-175, PAP-187, PAP-347, PAP-129, PAP-333, PAP-451 and every module entity.

**Definition of done**

* `workspaces`, `memberships` and `files` routers regenerated by the factory with PAP-268's tests passing unchanged; typecheck rejects a wrong input.
* A scratch entity defined in under 30 lines passes `entityConformance`, appears in OpenAPI, emits `record.created` and streams through a shape (integration).
* Cross-tenant list and get proven empty or `NOT_FOUND` through the PAP-34 harness; 409 precondition path tested.
* Cookbook with the timed walkthrough; comments on PAP-100, PAP-175, PAP-187, PAP-347; CHANGELOG under Platform.

**Test plan**

* Unit: option validation, DTO derivation from `drizzle-zod`, list SQL snapshot with filter, sort and cursor, error mapping table, hook ordering, shape exclusion of encrypted columns.
* E2E: CI compose: define a scratch entity, run the generated router through `callAs` for two tenants, assert isolation, events and idempotent replay; Playwright lists it through the typed client on a demo route.

**Demo**

Reviewer follows the cookbook: adds a `note` table, calls `defineEntity`, runs `pnpm gen:api`, and lists notes from Scalar with a filter and cursor in under ten minutes on the clock. Two minutes to review the recording.

**Edge cases**

* Table without `tenant_id` (global entity): `tenantScoped: false` required explicitly; list applies the PAP-34 global read policy.
* Composite natural keys or non-UUID ids: refused; entities use `id()` from PAP-32.
* Hook throws after `publish`: transaction rolls back both; documented.
* Very wide tables: shapes require an explicit column list above 40 columns.
