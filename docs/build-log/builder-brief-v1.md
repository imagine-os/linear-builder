## Operating mode (Justin's org policy "Git only: no PRs" overrides the plan's PR flow)
1. **Worktree per issue.** In the target repo: `git fetch origin main` (may fail if main does not exist yet), then `git worktree add /workspace/wt/PAP-<n> -b feat/PAP-<n>-<slug> origin/main` (if origin/main does not exist and you are NOT PAP-13, wait: see rule 4). Work only inside your worktree.
2. **Green before push.** Run the repo's full check (`pnpm check` = lint + typecheck + test + build, or whatever the repo defines) and make it pass before every push.
3. **Integrate to main yourself, no PR.** `git fetch origin main && git rebase origin/main`, re-run the check, then `git push origin HEAD:main`. If rejected as non-fast-forward, fetch, rebase, re-check, push again (up to 5 tries). Never force-push `main`. Never rewrite other people's commits. On a `pnpm-lock.yaml` rebase conflict: take the upstream lockfile (`git checkout --theirs pnpm-lock.yaml` semantics during rebase mean the upstream version; verify), run `pnpm install --lockfile-only`, `git add pnpm-lock.yaml`, `git rebase --continue`.
4. **Template repo ordering.** PAP-13 creates `origin/main` of the template. Every other template-repo issue does its research/writing first, then before pushing polls `git ls-remote origin main` every 60 s (up to 45 min) until main exists, then creates its worktree from origin/main, moves its files in, runs the check and pushes. If main never appears, commit on your local branch, push the branch `feat/PAP-<n>-<slug>` to origin and report that.
